## What was built

### Tier mapping — in the domain, not the component

`domain/flameTier.ts`. Deciding what a streak has *earned* is game logic, so it
is a pure function with tests, and the boundaries can later be changed — or
generated by the AI layer — without touching the drawing code. The component
owns only how a tier looks.

| Streak | Tier | Colour |
|---|---|---|
| 0 | 0 | grey, unlit, dimmed |
| 1–6 | 1 | orange |
| 7–13 | 2 | red |
| 14–29 | 3 | magenta |
| 30–59 | 4 | violet |
| 60+ | 5 | teal |

Boundaries are front-loaded on purpose: tier 1 arrives on day one, so a single
completion visibly lights the flame, and the gaps then widen (6, 7, 16, 30,
open-ended) so the high tiers stay rare enough to chase.

11 tests. Every boundary checked from both sides against a table transcribed
independently from `PLAN.md`; monotonicity across 400 days; a cross-check that
`daysToNextTier` always lands exactly one tier up; and that the tiers tile the
number line with no gaps or overlaps. Corrupted input (negative, `NaN`,
`Infinity`) falls back to unlit rather than producing a tier with no colour
token.

### The flame

Flat bold art: one silhouette, one soft inner core sitting low, one thin dark
outline. The outline is doing real work — a bright flame inside its own
coloured glow loses its edge and turns into a blob, and drawing the outline in
the page background colour cuts a crisp boundary between shape and halo.

Glow is a per-tier token in that tier's own hue, intensity climbing with the
tier. Tier 0 has none, because an unlit flame has earned nothing. These are
separate from the three `primary-hot` glow tokens by design — `CLAUDE.md`
sanctions flame hues "inside the flame and its glow".

### Motion

Flicker: 1.6 s, `transform` and `opacity` only, infinite, anchored at the base
so the flame licks upward rather than growing from its middle. Tier-up pulse:
620 ms, transform only, fires once and only on an *increase* — a corrupted
streak or a reset must never trigger a celebration, and first render must not
fire on every page load.

Verified in a real browser under both motion preferences:

| | normal | `prefers-reduced-motion: reduce` |
|---|---|---|
| animation-name | `flame-flicker` | `none` |
| duration | 1.6 s | — |
| animated properties | `transform`, `opacity` | `transform`, `opacity` |

## Findings

### 1. Dynamic class names would have silently produced no glow

`` `drop-shadow-flame-${tier}` `` is invisible to Tailwind, which scans source
text for literal class names. The utilities would never have been generated and
every flame would have rendered flat, with no error anywhere.

This is the second instance of the same failure mode — step 1 hit it when
`--text-*` tokens were tree-shaken because they were only referenced from inline
styles. Fixed with a static lookup map, and verified by grepping the built CSS
for all five utilities rather than trusting the source.

### 2. The outline scaled with the flame

A fixed `stroke-width` in viewBox units meant the outline grew with the shape:
a hairline at 22 px, a heavy cartoon border at 72 px. The outline wants constant
*visual* weight, not constant proportion, so it is now computed from the
rendered size — about 1.5 device pixels at any size, clamped at both ends.

Only visible by rendering both sizes together, which is the same check that
caught three defects in step 2.

### 3. Heatmap structure at zero intensity — step 2's outstanding item

The question was whether the grid reads when nothing has been logged. Rendered
both ways at 12 weeks, all cells empty:

- **On a `surface` card: it does not.** `heat-0` is `#14090E`, identical to
  `surface`, so the cells vanish entirely and an empty heatmap is a blank
  rectangle. That is "broken", not "sparse" — it fails the requirement.
- **On `bg-base`: it does.** `heat-0` sits one step above `#0A0509`, so the
  cells read as a grid defined by the gaps between them, exactly as specified.

**Constraint for step 4: the heatmap sits directly on the page background, not
inside a card.** No token change needed — `PLAN.md` asks for empty days to be
"bare surface cells", and that is precisely what `heat-0` on `bg-base` gives.
Putting it in a card would break it.
